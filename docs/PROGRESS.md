## 1. 저장소 확인과 구현 범위

`/Users/ddoni/dev`에는 이 프로젝트에 해당하는 기존 저장소가 없었다. 전달된 `/Users/ddoni/Downloads/marble_race_codex_plan`의 AGENTS.md와 docs/01~05, PROGRESS.md를 읽고 새 프로젝트 디렉터리를 만들었다. AGENTS.md 및 설계 문서 01~05는 원본과 바이트 단위로 일치한다. PROGRESS.md만 작업 결과로 갱신했다. Git 초기화·커밋·push·PR·배포는 하지 않았다. 기존 프로젝트와 다운로드 원본을 삭제하거나 수정하지 않았다.

Supabase·로그인·DB·에디터·스킨 업로드·공유·순위/결승/DNF·시드 배정·속도 변경은 구현하지 않았다. P1의 공개 JSON 계약도 선행 구현하지 않았으며, P0의 내부 타입과 고정 fixture만 사용한다. 익명 고정 구슬을 사용하므로 참가자 정보 입력이나 저장도 없다.

## 3. 확정한 P0 기술 결정

- React는 UI와 250ms 간격 snapshot만 소유한다. 프레임 좌표는 React 상태에 넣지 않는다.
- `src/game/core`: React/DOM/Pixi/서버 의존성 없는 SimulationCore, FixedStepper, 계측 통계. ESLint로 주요 금지 import/global을 검사한다.
- `src/game/physics`: Rapier world 생성·step·pose 읽기·free. 비동기 WASM 초기화를 공유하고 실패 시 재시도 가능하게 한다.
- `src/game/renderer`: Pixi 8의 비동기 Application.init, WebGL 우선, DPR 최대 2. 자동 ticker를 멈추고 runtime의 RAF 하나에서 물리와 수동 render를 수행한다. ResizeObserver는 dispose에서 해제한다.
- `src/game/runtime`: 브라우저 수명주기, 지연 로딩, 오류 복구, UI 통지, 60초 측정. AbortSignal로 초기화 완료 전 unmount를 처리하고 늦게 완성된 인스턴스도 해제한다. dispose는 중복 호출 가능하다.
- fixed dt는 1/60초, 입력 real delta는 최대 0.1초, 프레임당 최대 8 step이다. 적체는 현실 시간만 버리고 물리 tick을 건너뛰지 않는다. 이전/현재 pose를 렌더 보간한다.
- pause는 물리 누적을 비운다. reset은 새 world를 만들고 tick=0/ready로 복귀한다. 숨김 탭은 자동 pause하고 다시 표시되어도 사용자가 재개한다. 숨김 상태에서는 측정도 취소한다.
- `classic-v1-p0`: 중력 y=9.81, 반지름 0.22, 질량 1, 마찰 0.35, 반발 0.25, 범퍼 반발 0.9, 반발 조합 Max, 마찰 조합 Average, solver 4회, 구슬 CCD ON. P0 제안 프로필이며 출시용 물리/재현성 계약은 P2에서 확정한다.
- 회전봉은 position-based kinematic body에 다음 tick의 회전을 지정한다. `initial + speed * tick * fixedDt`를 사용한다. CSS 애니메이션이나 추가 임의 impulse로 물리를 대체하지 않는다.
- Worker/OffscreenCanvas는 도입하지 않았다. 아래 단일 기기 측정으로 범용 성능을 보장하지 않으며, 모바일 측정 후 필요성을 재검토한다.
- 맵 hash는 고정 fixture의 `JSON.stringify` 바이트에 SHA-256을 적용한 식별자다. P1의 임의 문서 canonical serialization 구현을 의미하지 않는다.
- Next dev 16.4가 AGENTS.md에 자동 블록을 추가하는 것을 확인해 `agentRules: false`로 설정하고 원본을 복원했다.

## 4. 실행 방법

```sh
cd /Users/ddoni/dev/marble-race
npm ci
npm run dev
```

기본 경로는 `http://localhost:3000/play`다. 개발 환경에서는 HUD가 표시된다. 프로덕션 HUD와 읽기 전용 테스트 bridge는 `/play?debug=1`에서만 활성화한다. bridge는 서버 API가 아니며 실제 물리 좌표를 React 상태에 저장하지 않는다.

```sh
npm run lint
npm run typecheck
npm run test
npm run build
npm run start -- --hostname 127.0.0.1 --port 3100
# 별도 터미널
npx playwright install chromium firefox webkit
npm run test:e2e
BENCH_HEADED=1 npm run benchmark
```

benchmark는 이미 실행 중인 localhost:3100 프로덕션 서버를 대상으로 한다. `BASE_URL`로 변경할 수 있다. 20개와 100개 장면을 각각 60초씩 3회 실행하고 `test-results/benchmark.json` 및 `test-results/desktop.png`를 만든다. `BENCH_SCENE=100`을 추가하면 100개 장면만 재측정한다. `BENCH_HEADED=1`이면 전경 Chromium, 생략하면 headless이므로 결과를 구분해야 한다. UI에서도 장면을 선택하고 '60초 측정 시작'으로 재현할 수 있다. 측정 중 pause/reset/장면 변경/숨김이 발생하면 해당 미완료 측정은 결과로 남지 않는다.

`test-results/`는 임시 결과이며 Playwright 재실행 때 초기화될 수 있다. 이번 확정 계측은 `docs/p0-benchmark.json`에 별도로 보존한다. `test:db`는 P5 미구현이므로 가짜 성공 스크립트를 만들지 않았다.

### 수정하거나 구분한 검증 실패

- 최초 context-loss E2E는 Next의 route announcer와 앱 오류창 모두를 `role=alert`로 선택해 실패했다. 앱 오류창으로 선택자를 한정한 뒤 3개 브라우저에서 재검증했고 최종 18개가 통과했다.
- React Doctor `--scope changed`는 Git HEAD가 없어서 실행 불가였다. Git을 초기화하지 않고 full 진단으로 대체했다. 브라우저 전용 경계를 명시하고 결과 키를 안정화한 뒤 74→92점으로 개선했다.
- Ego 브라우저에서는 로딩과 tick 진행을 확인했으나 screenshot CDP timeout과 약 1fps가 관찰됐다. 원인은 확정하지 않았다. 정식 성능 표는 별도 표준 Chromium 전경 실행의 결과이며 Ego 성능을 검증 완료로 표시하지 않는다.
- npm 12의 `npm install --package-lock-only`는 remote tarball 정책(EALLOWREMOTE) 때문에 실패했다. 의존성 버전·URL·integrity를 바꾸지 않고 루트 engines 메타데이터만 동기화했고 최종 npm ci와 전체 기본 검사를 다시 통과했다.

`createBenchmarkMap → loadMapScene → canonicalizeMap → 내부 Scene → Rapier/Pixi` 경로로 P0 장면을 전환했다. 기본/스트레스의 도형 수와 기존 출발 좌표를 유지하고 ID는 고정 UUID로 옮겼다. 런타임 hash는 이제 MapDocument canonical hash다. **P0의 옛 내부 Scene JSON hash 및 성능 결과와 구분**한다.

loader는 검증을 마친 객체를 ID 순서로 생성하고 문서 spawn에서 슬롯을 얻는다. 기존 fixed timestep/pause/reset/dispose/Strict Mode 대응/자원 계측을 유지했다. React는 250ms snapshot만 받고 프레임 좌표는 엔진 안에 남는다. 물리 초기화/렌더러 로딩은 클라이언트 지연 로딩을 유지한다.

P1 미리보기는 wall/circle/bumper/rotor를 지원한다. circle은 fixed ball로 연결한다. 범퍼의 P1 프리뷰 반발력은 soft=0.4 / normal=0.65 / strong=0.9이고 기존 P0 범퍼는 strong이다. 동일한 구슬 반지름·질량·마찰·반발·solver·CCD를 유지했다. 움직이는 발판은 계약·경로·초기 위치만 검증하며, 미리보기로 열면 P2 지원 예정 메시지를 표시하고 기존 장면을 보존한다. loader도 unsupported 오류를 반환하여 조용히 객체를 누락하지 않는다. ## 11. 사용자 추가 요청: 긴 코스와 이름·번호 입력 (2026-10-14)

### 구현과 결정

P1 후속 사용자 요청인 “판을 더 길게, 사용자 이름과 숫자 커스텀”만 추가했다. P2 전체 구현으로 표시하지 않는다. 설치 의존성과 lockfile, 물리 프로필 및 고정 timestep은 변경하지 않았다. 저장소는 여전히 Git 미초기화 상태다. 기존 파일 삭제, Git 초기화·커밋·push·배포는 실행하지 않았다.

- 세 코스를 월드 `24×28`에서 `24×72`로 확장했다(높이 약 2.57배). 황금 지그재그는 경사 11층, 홍련 범퍼는 범퍼 70개, 청룡 회전봉은 회전봉 18개·6층이다. 경계 벽을 포함한 전체 장애물 수는 각각 21/78/30개다.
- 기존 v1 문서는 `src/game/templates/v1.ts`로 보존하고 세 코스에 `*-v2` ID와 새 UUID 영역을 부여했다. v1 고정 해시 3개 보존을 별도로 검사했다. 맵 계약 및 canonical 알고리즘 버전은 변경하지 않았다.
- 기본 화면은 선두 구슬을 따라 세로로 이동한다. 화면 비율에 따라 최소 약 36단위 높이를 보여 주며, 끝에서는 월드 경계로 제한한다. `전체 코스 보기`와 `구슬 따라가기` 전환은 물리를 바꾸지 않는다. reset 시 따라가기 카메라는 출발점으로 돌아간다.
- 파칭코 외관을 유지하면서 세로 캔버스, 단계 표식, 추적 위치, 모바일 비율을 추가했다. `GameBoard`와 `ParticipantPanel`을 분리했다. 카메라와 구슬 라벨은 Pixi 렌더러에 있고 프레임 좌표를 React 상태에 넣지 않는다.
- `내 구슬 만들기`: 줄바꿈 또는 쉼표로 이름·숫자·짧은 문구 2~100개를 입력하고 `구슬에 적용`하면 **실제 물리 구슬 수**가 입력 개수로 바뀐다. 최대 입력은 8,192 UTF-16 code unit, 이름은 기존 Zod 계약의 24 code point 한도다. 빈 항목은 무시한다. 입력 검증 실패 시 현재 장면을 유지한다.
- 같은 이름은 허용하되 참가자 UUID는 각각 다르다. `001`은 문자열로 보존한다. `연속 번호로 채우기`는 시작 정수 -999999~999999와 개수 2~100을 받아 목록을 만든다. 번호를 채운 뒤 적용 버튼으로 반영한다.
- 참가자 목록은 맵 JSON/hash와 분리한다. reset과 세 기본 코스 전환에서 목록을 유지하며, 다시 적용하면 출발점으로 초기화한다. 20/100개 빠른 선택은 해당 개수의 1부터 시작하는 번호 목록으로 교체한다. P0 계측 장면은 종전처럼 20/100개만 지원하므로 사용자 개수가 다른 상태에서 계측 장면을 선택하면 20개 기본 번호로 바뀐다.
- 이름표는 구슬 위에 표시하고 8 code point를 넘으면 줄인다. 전체 이름은 `현재 적용된 구슬` 목록에서 확인한다. 20개 이하는 기본 표시, 21개 이상은 기본 숨김이며 `이름 표시`로 켤 수 있다. 밀집한 구슬의 이름표는 겹칠 수 있다. 이름/표시 여부는 물리 질량·크기·충돌에 영향을 주지 않는다.
- 이번 목록은 페이지 메모리에만 있다. 새로고침·페이지 이탈 후 복원, 이름 목록 파일 저장, 자동 순위·당첨 결과·시드 배정은 추가하지 않았다.

## 13. 반복 결과 원인 수정과 경기 몰입감 (2026-10-14)

### 원인과 범위

사용자가 “모든 결과가 똑같다, 몰입감이 필요하다”고 요청했다. 소스에서 `loadMapScene`이 출발 슬롯의 앞쪽 count개를 고정 선택하고 `RapierPhysics`가 참가자 배열 순서로 동일한 위치·초기 속도를 생성하며, reset도 같은 scene으로 world를 만드는 것을 확인했다. 고정 timestep 자체는 의도한 동작이다. 일반 플레이의 출발 입력까지 고정되어 같은 궤적이 반복되던 것이 원인이다. 기존에는 결승선 그림만 있고 통과 판정·우승 화면도 없었다. 브라우저 재현 테스트는 사용자 요청에 따라 하지 않았다.

이번 변경은 후속 요청을 위한 **첫 도착 승리 모드와 연출**이며 P2 전체 완료가 아니다. 다운로드 원본의 계획 문서를 새 기능 전체에 대한 사용자 승인으로 취급하지 않았다.

### 구현·결정사항

- 일반 템플릿/가져온 맵을 처음 열거나 `새로 섞기`, 종료 후 `다시 한 판`을 누르면 crypto uint32 seed를 생성한다. core의 `mulberry32-v1`과 rejection sampling 기반 Fisher–Yates로 검증된 전체 출발 슬롯을 섞어 참가자에게 배정한다. 참가자 순서·ID·이름과 구슬 번호는 유지한다.
- 같은 시드 스트림에서 초기 수평 속도 [-1.3, 1.3), 아래 방향 속도 [0, 0.5)를 생성해 출발 궤적도 바뀌게 했다. 모든 구슬은 동일한 생성 규칙과 물리 프로필을 사용한다. 매 tick에 난수를 넣거나 진행 도중 위치·힘으로 승자를 조작하지 않는다. 새 경기에서 동일한 승자가 나오는 것은 가능하다.
- 초기 조건과 최초 도착 판정의 내부 simulationVersion은 `first-finish-v1`이다. debug bridge에 seed, 배정 슬롯, 초기 속도를 제공한다. map JSON/hash를 바꾸지 않으며 전체 RunManifest 저장/재생 계약은 아직 구현하지 않았다.
- 3·2·1 카운트다운 중에는 물리를 진행하지 않는다. 카운트다운 일시정지/재개, 새로 섞기 시 초기화, 숨김 탭 일시정지는 기존 단일 RAF 안에서 처리한다. DOM 타이머를 추가하지 않았다.
- 각 고정 tick의 previous/current 중심을 연결해 아래 방향 결승선 교차와 교차 x 범위를 판정한다. 같은 tick의 crossingFraction을 1,000,000 단위로 반올림해 최초 키가 같은 구슬은 공동 1위로 표시한다. 도착 시간은 tick 내부 선형 보간 근삿값이다.
- **첫 도착 tick에서 월드 전체를 정지**한다. 이후 순위는 수집하지 않으며 collider 개별 제거도 하지 않는다. 따라서 전체 완주 순위·꼴찌·지정 순위 모드로 설명하지 않는다. 7,200 tick(시뮬레이션 120초)에 도착자가 없으면 완주자 없는 시간 초과 화면을 표시한다. 비정상 수치는 기존 오류 경로로 처리한다.
- 오른쪽 중계판에 선두/추격 3개 이름·번호와 세로 진행률을 표시한다. 이는 확정 순위가 아닌 `예상 진행 순서`다. 선두 교체 문구와 금색 구슬 테두리, 속도 방향 잔상을 추가했다. React에는 기존 250ms 간격 요약만 전달하고 프레임별 pose를 넣지 않는다.
- 마지막 5단위 구간은 0.4배 재생으로 긴장감을 준다. 고정 dt/중력/solver는 그대로이며 현실 시간에 실행할 tick 수만 줄인다. 우승 시 이름·구슬 번호·통과 시간과 금색 결과 화면을 표시한다. 공동 1위는 함께 표시한다.
- 소리는 기본 OFF이며 사용자가 켜면 Web Audio 합성음으로 카운트다운·출발·선두 교체·우승을 알린다. 외부 음원·다운로드가 없고 AudioContext는 dispose에서 닫는다. CSS 모션 축소와 렌더러 초기 모션 축소 설정에서 추가 애니메이션/잔상을 줄인다.
- P0 및 60초 계측은 고정 슬롯·초기 속도 0, 카운트다운·승패·슬로모션 없는 기존 모드를 사용한다. 계측 종료 후 새로 섞으면 일반 맵은 경기 모드로 돌아온다.
- 설치 버전은 2절과 동일하다. package.json/lockfile, 독자 템플릿과 canonical hash는 변경하지 않았다. Git 저장소는 미초기화 상태를 확인했고 초기화·커밋·push·배포·기존 파일 삭제를 하지 않았다. 작업 전 소스와 문서 복사본은 대화 작업 폴더 `work/race-immersion/`에 보존했다.

## 15. 능동 장애물·구간별 구조·정체 방지 (2026-10-14)

### 요청과 원인 조사

사용자는 구슬이 장애물에 걸려 멈추지 않아야 하고, 모든 장애물이 구슬을 역동적으로 쳐내며, stage별 구조가 달라야 하고, 병목이 없어야 한다고 요청했다. 기존 v3 소스에는 긴 정적 경사, 밀집된 고정 핀, 폭 1.2 목, 구슬 간 충돌 및 기본 마찰/수면이 함께 있었다. 이 조합은 구슬을 받치는 면과 구슬 적층을 만들 수 있다. 관성에 의존하는 반발력만으로는 정지한 구슬을 다시 움직이지 못한다. 이는 소스 기반 구조 분석이며 실제 정체를 재현한 테스트 결과가 아니다.

### 구현 및 사용자 경험

- 세 기본 코스를 v4로 추가하고 종전 v3 문서를 `templates/v3.ts`에 보존했다. v1~v3 map 내용과 hash는 유지한다(v1의 공유 Template 타입에는 화면용 stages 선택 속성만 추가). v4 객체는 별도 UUID namespace 10/11/12를 쓴다.
- 코스를 네 구간으로 나눴다. 회전 스위퍼, 다이아몬드 모양 킥 범퍼, 엇갈린 핀 배열을 서로 다른 순서로 배치하고, 마지막 구간은 코스마다 삼중 회전/킥 게이트/이중 터빈으로 다르게 만들었다. 긴 정적 경사와 핀을 겹쳐 놓은 받침 구조를 없앴다.
- 내부 장애물은 강한 범퍼와 회전봉이다. 정적 벽 8개는 외곽과 깔때기 가이드 역할만 한다. 구간 경계와 이름을 Pixi에 표시하고 중계판에도 현재 구간을 제공한다. 구간 명칭은 Template/Scene의 화면 메타데이터이며 물리 map JSON 밖에 둔다. JSON 재입력으로 물리 배치는 보존되지만 템플릿의 구간 명칭은 가져오지 않는다.
- 깔때기는 유지하되 통로 폭을 **1.2 → 3.6**으로 확대했다. finish는 `{ left: 10.2, right: 13.8, y: 70.5 }`다. 구슬 지름 0.44의 약 8.18배다. 끝에 구슬을 한 줄로 모으던 중심 핀과 과밀한 목 배치를 없앴다. 깔때기 상부에는 8개 킥 범퍼가 남는다.
- 새 규칙은 **구슬끼리는 서로 통과하고, 구슬과 장애물은 물리 충돌**한다. 구슬 적층과 결승 앞 줄서기를 막기 위한 아케이드 모드 선택이다. UI 하단에 `구슬끼리는 통과 · 정체 시 자동 킥`을 표시한다. 서로 밀어내는 classic 모드와 동일한 게임이라고 설명하지 않는다.

### 명시적인 물리 버전 분리

`MapDocument.physicsProfile` 계약에 `arcade-flow-v1`을 추가했다. v4는 이 프로필을 JSON과 canonical hash에 포함한다. 기존 `classic-v1`/P0와 과거 템플릿의 의미는 유지한다. 반지름·질량·중력·1/60 고정 timestep·solver·CCD는 기존 값을 사용한다.

- `arcade-flow-v1`의 collision groups: 장애물 `0x00010002`, 구슬 `0x00020001`. 구슬끼리 접촉을 생성하지 않는다. 구슬 sleep은 끈다.
- 장애물 마찰 0.03, 마찰 조합 Min을 사용해 가이드 레일 위에서 버티는 힘을 줄인다. 구슬의 크기/질량 등은 이름·외형과 무관하게 동일하다.
- `physics/ArcadeFlow.ts`가 매 물리 tick의 접촉을 읽는다. 넓은 영역에서 가까운 후보만으로 발사하지 않고 실제 contact distance ≤0.01인 접촉을 확인한다. 같은 구슬의 후보는 canonical 생성 순서로 정렬하고 하나를 선택한다. 구슬당 12 tick 쿨다운을 적용한다.
- 범퍼/회전봉의 접촉 방향으로 제한된 impulse를 가한다. 원 꼭대기에 균형 잡힌 구슬에는 옆 방향 힘도 가한다. 이 기능은 단순 restitution과 달리 정지 상태에서도 에너지를 넣는 **능동 아케이드 킥**이다.
- 아래로 0.5 단위 진행하지 못한 상태가 120 tick(시뮬레이션 2초) 지속되면 탈출 impulse를 적용한다. 모든 구슬에 같은 기하/속도 규칙을 쓰며 참가자 이름·ID·순위는 참조하지 않는다. 순간이동·임의 삭제·진행 중 난수 주입은 없다. 속력은 18로 제한한다.
- 실제 킥의 object ID/tick을 렌더러에 전달하여 해당 범퍼 테두리가 밝아지고 퍼지게 한다. 모션 축소에서는 확대 연출을 줄인다. 프레임 pose/접촉 내역을 React 상태에 넣지 않으며 별도 RAF/타이머를 추가하지 않는다.
- 새 실행 버전은 `arcade-flow-first-finish-v1`, 계측 모드는 `arcade-flow-benchmark-v1`이다. debug bridge에는 프로필과 실제 실행 시 누적되는 kicks/assists 카운터를 제공한다. 이번 세션에서 그 수치를 실측하지는 않았다.
- P0 계측은 classic 규칙을 유지한다. v4 맵에서 60초 계측을 선택하면 초기 출발 조건은 고정하되 **그 맵의 arcade-flow 물리**를 계측한다. 예전 classic 수치와 같은 조건으로 비교하지 않는다.
- 최초 도착 시 경기 종료, 공동 1위 및 120초 timeout은 유지한다. 경기 종료로 전체 월드가 정지하는 것은 경기 중 정체와 구분한다. 전체 완주 순위와 끝까지 모든 구슬을 보내는 모드는 추가하지 않았다.

## 16. 레퍼런스 재관찰과 네온 레일·카메라·입력 흐름 (2026-10-14)

### 실제로 관찰한 레퍼런스

사용자가 [Marble Roulette](https://lazygyu.github.io/roulette/)를 더 확인해 비슷한 느낌으로 만들도록 다시 요청했다. 이번 명시적인 조사 요청으로 Ego 브라우저의 새 조사 작업 공간 4/p1에서 공개 사이트를 열었다. 과거 사용자가 제어를 가져간 작업 공간 3은 재접속/회수하지 않았다. 이번 공간은 관찰 종료 후 `finish({keep:[]})`로 정리했다.

- 첫 맵 `운명의 수레바퀴`: 대기, 시작, 실제 중간 주행, 결승/우승 화면을 관찰했다.
- 두 번째 맵 `버블팝`: 선택 후 대기, 시작, 완료 화면을 관찰했다. 전체 주행의 연속 녹화나 정량 프레임 분석은 하지 않았다.
- 관찰된 특징은 거의 검은 전체 화면, 밝은 레일과 움직이는 장애물, 대기 시 크게 보이는 구슬, 구슬 아래 색상별 이름, 좌측의 긴 미니맵, 우측 참가자 표시, 작은 좌하단 입력·맵 패널, 시작 후 패널 숨김, 결승 코스 위 우측 하단의 큰 우승자 표시다.
- 참고 이미지는 대화 작업 폴더 `work/reference-study-v2/reference-*.png`에 저장해 열어 보았다. 이는 외부 레퍼런스 이미지이며 새 구현 스크린샷이 아니다. 참고 사이트의 소스·맵 좌표·스킨 이미지·광고를 코드나 서비스 자산에 복사하지 않았다.

### 구현

1. **코스 중심 화면**: Pixi 캔버스가 화면 전체를 사용한다. 설정은 캔버스를 줄이지 않는 좌하단 760px 이내 패널로 변경했다. 닫으면 작은 설정/새로 섞기/시작·일시정지 컨트롤만 남는다. 코스 카드는 select로 정리하고, 기존 이름 입력·번호 생성·20/100개·계측/JSON 기능은 유지한다.
2. **선명한 구슬과 네온 레일**: 밤 테마의 격자 점을 제거하고 밝은 레일과 청록색 회전봉, 6색 구슬과 더 큰 이름표를 사용한다. 좌측 미니맵을 길게 표시하고 오른쪽 선두 표시의 카드 배경을 없앴다. 긴 이름은 12 code point 이후 생략하며 참가자 원문은 유지한다.
3. **시네마틱 카메라**: 출발 전에는 구슬 무리 크기와 뷰포트를 기준으로 확대하고, 출발 후 자동 배율/추적 중심을 지수 보간하여 주행 배율로 전환한다. 사용자 확대 배율은 별도로 유지한다. pause/reset/이름 보기 조작이 physics pose를 바꾸지 않도록 렌더러 안에서만 처리한다. 모션 축소에서는 보간을 줄이고 바로 목표 화면으로 이동한다.
4. **중앙 출발 대형**: arcade 모드에서는 검증된 슬롯 중 출발 영역 중앙에 가까운 필요한 수를 고른 뒤 seeded shuffle한다. 소수 참가자를 멀리 흩어놓지 않고 함께 크게 보여준다. 이름별 출발 배정과 초기 속도는 계속 seed에서 생성한다. 이 초기 조건 변경을 반영하여 simulationVersion을 `arcade-flow-first-finish-v2`로 올렸다. 물리 프로필 `arcade-flow-v1`의 접촉/탈출 규칙은 그대로다. P0 고정 배정은 유지한다.
5. **입력 후 바로 시작**: 기본 예시는 6명이다. `시작`은 입력을 검증하고 적용된 명단과 다르면 새 런타임 초기화 완료 후 카운트다운을 시작한다. 별도의 `구슬에 적용` 버튼도 유지한다. 유효하지 않은 입력이면 오류를 표시하며 기존 장면을 보존한다. 일시정지 `재개`는 현재 경기를 그대로 재개한다.
6. **우승 표시**: 중앙의 화면 전체 덮개/금색 카드를 없애고 코스가 보이는 우측 하단에 큰 참가자 색상 이름과 통과 시간을 표시한다. 현재 경기 규칙은 첫 도착 승리이며 전체 순위·마지막 도착·다중 당첨으로 확장하지 않았다.

## 17. 입구 액션 강화 v6 (2026-10-14)

## 18. 실시간 이름 반영과 이름*수량 입력 (2026-10-14)

### 구현과 결정

- 이름 입력의 `onChange`에서 검증된 명단을 바로 반영한다. 별도의 적용 버튼을 제거했다. 이름 예시와 연속 번호 생성도 같은 반영 경로를 사용한다.
- `민수*9, 지영*3`은 민수 9개 + 지영 3개, 총 12개의 참가자로 펼친다. 구슬 라벨에는 이름만 표시한다. 쉼표·줄바꿈, 배수 없는 이름(1개), 이름/배수 주변 공백을 지원한다. 별표는 수량 구분자로 사용하며 `이름*2*3` 같은 중첩 문법은 거부한다.
- 배수는 1~100의 십진 정수, 펼친 합계는 기존 계약과 같은 2~100개다. `이름*`, 0, 음수, 소수, 비숫자, 100개 초과 합계는 오류를 안내하며 마지막 유효 명단을 유지한다. 입력 전체를 비우거나 구슬 하나만 남겨도 기존 명단을 유지하고 최소 수량 안내를 표시한다. 거대한 배수는 배열 생성 전에 차단한다.
- 이름 검증과 NFC 정규화는 기존 Zod 이름 스키마를 재사용한다. 배수 합산 카운트는 UUID를 생성하지 않는 순수 파서로 계산하고, 확장한 참가자는 각자 고유 ID를 갖는다. 현재 입력에서 유지되는 배열 위치는 기존 ID를 재사용한다.
- 이름만 변경하면 런타임의 명단과 Pixi Text를 갱신한다. 준비 상태에서는 world/canvas를 재생성하지 않으며 위치와 seed를 유지한다. 경기 진행·일시정지·결과 상태에서 실제 명단이 바뀌면 새 대기 경기로 reset한다.

## 21. 수천 구슬 입력·전원 종료·우측 전체 순위 (2026-10-14)

요청: 몇천 개 구슬을 지원하고, 첫 구슬 도착으로 끝내지 않으며 모든 구슬이 끝났을 때 종료하고, 우측에 전체 순위를 계속 표시한다.

### 입력 및 출발

- 참가자 계약/배수/번호 생성/물리 생성 상한을 10,000개로 확장했다. `민수*3000`과 여러 이름·배수를 합친 총 10,000개까지 입력할 수 있다. 원문 입력 제한은 300,000 code unit이다. 이름 길이/안전한 텍스트/ID 중복 검증은 유지한다. 같은 배열 위치의 기존 참가자 ID를 입력 파서에서도 재사용한다.
- 1,000개/5,000개 빠른 설정을 추가했다. 현재 적용 명단의 DOM 미리보기는 앞 100개로 제한하고 전체 결과는 순위표로 안내한다. 실시간 이름 반영과 수량 변경의 dispose/재초기화 경로를 유지한다.
- 아케이드 맵은 기존 출발 영역의 검증된 비중첩 슬롯을 재사용한다. 인원이 슬롯 수보다 크면 seeded shuffle로 전체 참가자를 무작위 순서에 배정하고, 슬롯 수만큼의 묶음을 60 tick(1 simulation second) 간격으로 출발시킨다. 현재 템플릿은 100개의 슬롯이므로 최대 100개씩 출발한다. 모든 수천 구슬을 같은 순간 같은 슬롯에 겹쳐 활성화하지 않는다.
- 출발 대기 body는 실제 Rapier body/collider로 준비하지만 비활성 상태로 둔다. launchTicks는 시드에서 정해진 배정과 함께 보관하며 고정 tick에 활성화한다. 화면에는 대기 구슬을 숨기고 대기 수를 표시한다. 슬롯 배정/초기 속도/출발 시각이 새 경기마다 seed로 결정되며 사용자 입력 순서로 첫 묶음을 지정할 수 없다.
- 묶음별 출발은 동시 출발과 다른 조건이다. 통과 시간은 경기 시작 이후 절대 simulation time이며 먼저 출발한 묶음이 빠른 순위에 유리할 수 있다. 균등 승률이나 수천 구슬 동시 출발 성능을 검증했다고 주장하지 않는다.
- classic/P0 맵은 기존 슬롯 수 검증과 20/100개 계측 장면을 유지한다. 임의 classic 맵에서 수천 개를 실행한다고 표시하지 않는다. P0 계측 장면에서 1,000/5,000개 설정을 누르면 아케이드 코스로 전환한다.

### 전원 처리와 순위

- 기본 레이스 코어를 `AllFinishRace`로 교체했다. 구슬별로 결승선 하향 선분 교차를 확인하고 이전에 처리한 구슬은 다시 기록하지 않는다. 같은 tick은 교차 fraction을 1,000,000으로 양자화한 키로 정렬하며 동일 키는 공동 순위다. 공동 1위 두 개 뒤 다음 순위는 3위가 된다.
- 매 tick의 도착을 누적하고 완주 body를 비활성화한다. 해당 구슬은 킥/정체 보조/물리 pose 갱신/본 화면/미니맵의 활성 그룹에서 제외한다. 이전 완주 구슬이 결승 통로에 남아 막지 않으며, 순위 기록과 통과 시간은 남긴다.
- 첫 도착 및 기존 7,200 tick 시간 초과로 전체 경기를 멈추지 않는다. 대기 중이거나 아직 주행 중인 구슬이 있으면 계속 진행한다. 전원 결승 통과 또는 명시적인 코스 이탈 DNF로 전원 처리가 끝났을 때만 종료한다. 이탈은 월드 밖으로 1단위 이상 나가거나 월드 하단보다 1단위 이상 내려간 경우다. NaN 등 비정상 물리 상태는 여전히 실행 오류이며 DNF로 숨기지 않는다.
- 카메라/현재 선두/구간 표시는 활성 구슬만 따라간다. 첫 완주 직후 우승 장면에 고정하지 않는다. 200개 초과에서는 결승 슬로모션을 끄고, 소규모에서도 첫 완주 뒤에는 정상 속도로 남은 구슬을 진행한다.
- 우측에 전체 확정 순위, 이름, 구슬 번호, 통과 시간과 완주·남은 구슬·출발 대기·DNF 수를 표시한다. 확정 순위와 주행 중 예상 선두는 구별한다. DNF는 완주 순위 뒤 별도 상태로 표시한다. 종료 후에도 전체 결과를 스크롤할 수 있다.
- 전체 순위는 가상 스크롤을 사용하여 보이는 행과 주변 행만 DOM에 생성한다. 누적 결과 snapshot은 결과 개수가 바뀔 때 갱신한다. React는 여전히 프레임별 좌표를 보관하지 않는다.

### 대규모 표시와 버전

- 구슬마다 Graphics를 생성하는 방식에서 공유 원형 Texture + tint Sprite로 변경했다. 화면 밖·대기·완주 구슬은 렌더에서 숨긴다. 대규모 경기에서도 각 활성 구슬은 Rapier 물리로 움직이며 숫자 합계만 모사한 연출로 대체하지 않았다.

## 24. 구슬 수에 따른 출발 공간 확장·전체 미리보기·동시 출발 (2026-10-14)

### 출발 배치와 물리

- 순차 출발용 launchTicks/launchQueue를 제거했다. 모든 참가자의 실제 Rapier body/collider는 초기화 시 준비하고 활성 상태로 둔다. ready/countdown에서는 기존 코어가 tick을 진행하지 않으며, 시작 시 같은 simulation tick부터 전원에 중력을 적용한다. 완주 이후의 비활성화와 전체 종료·순위 누적은 유지한다.
- 기존 슬롯보다 참가자가 많으면 순수 코어 함수 `expandedStart`가 참가자 수에 맞춘 넓은 출발 상자를 만든다. 열 수는 `ceil(sqrt(count*2))`, 행 수는 `ceil(count/columns)`, 중심 간격은 0.56이다. 반지름 0.22(지름 0.44)를 유지하고 마지막 불완전 행은 중앙에 맞춘다. 참가자 배정은 전체 슬롯에서 seeded shuffle한다.
- 새 출발 상자에는 상단/측면 벽을 만들고, 기존 코스의 옛 상단 덮개를 실행 장면 복사본에서 열어 연결 깔때기로 이어준다. 원본 MapDocument는 변형하지 않는다. 기존 장애물·왕복 끝점·구간·결승선을 같은 x/y 오프셋으로 옮긴다. 이 오프셋으로 생긴 확장 월드 안에서 결승·코스 이탈·진행률을 계산한다.
- v10 원본 맵의 형상/hash 및 JSON 계약의 월드/오브젝트 상한은 유지한다. 확장 출발 구역은 count와 버전으로 결정되는 **실행 장면**이며, 원본 JSON에 저장되지 않는다. 실행 장면의 실제 월드는 원본 맵보다 클 수 있고, 출발 연결 벽이 추가된다. 원본 맵의 상한을 확장 실행 장면의 수량/월드 크기 상한과 혼동하지 않는다.
- diagnostics에 `startLayout`(버전·행/열·간격·출발 bounds·코스 오프셋), 실제 assignedSlots, seed와 초기 속도를 제공한다. 레이스 simulationVersion은 `arcade-flow-all-finish-expanded-start-v1`, 확장된 아케이드 계측은 `arcade-flow-expanded-start-benchmark-v1`로 구분한다. 전체 영구 manifest/독립 JSON으로 실행 장면을 내보내는 기능은 아직 미구현이다.
- 기존 100개 이내 기본 템플릿과 classic/P0 계측 출발은 유지한다. 검증된 슬롯이 부족한 아케이드 실행만 확장한다. 임의 classic 맵의 대규모 출발 지원을 추가했다고 표시하지 않는다.

## 25. 입체 구슬·입력값 각인·긴 회전 게이트 코스 v11 (2026-10-14)

요청: 구슬의 입체감과 디자인을 강화하고, 이름/숫자를 구슬에 새기며, 결과가 너무 빨리 나오지 않도록 장애물과 배치를 재구성한다.

### 구슬 디자인과 실시간 입력

- 렌더러 전용 `MarbleArt`가 Canvas 2D로 6색 공용 구슬 텍스처를 만든다. 밝은 상단에서 어두운 하단으로 이어지는 구형 음영, 얇은 반사 테두리, 곡면 광택/하이라이트, 하단 그림자로 유리·래커 느낌을 표현한다. 외부 이미지·폰트·네트워크 요청은 추가하지 않는다.
- 종전 200개 이하의 구슬 안에 임의 순번을 찍던 Text를 제거했다. 실제 검증된 참가자 name을 별도 각인 sprite로 표시한다. 이름, 연속 번호 생성기의 실제 시작 번호/숫자, 짧은 문구가 그대로 들어가며, `민수*9`는 9개 모두 `민수`로 각인된다. 24글자까지 최대 4줄로 맞추고 임의 순번으로 대체하지 않는다.
- 같은 이름의 각인은 texture atlas의 같은 셀을 공유한다. 구슬 수 300 이하에서는 96px, 그 이상에서는 48px 셀을 쓰며 1024px 페이지에 담는다. 따라서 `민수*5000`은 구슬별 Text/글자 이미지 5,000장을 만들지 않는다. 모든 활성 구슬에는 각인 sprite가 있고, 화면 밖/완주 구슬은 렌더러에서 숨긴다.
- 이름 변경은 기존 runtime의 `setParticipants`→`setParticipantNames`에서 각인 텍스처를 다시 연결하고 대기 화면을 즉시 그린다. 활성 경기/결과 명단을 바꾸면 기존 규칙대로 새 명단의 ready 상태로 reset한다. 반복 편집으로 예전 이름을 계속 쌓지 않도록 현재 고유 이름 수 + 128을 넘는 캐시는 비우고 현재 명단으로 재작성한다.
- 구슬 표면의 조명과 각인은 화면에서 읽을 수 있게 똑바로 유지한다. Rapier body의 회전과 회전 장애물의 실제 회전은 유지한다. 각인은 이름표 토글과 무관하게 보이며, 구슬 아래의 추가 이름만 `이름표 표시/숨기기`로 제어한다. 입력 도움말도 각인을 안내하도록 수정했다.

## 26. 오른쪽 끝 축의 전체 폭 결승 회전봉 v12 (2026-10-15)

## 27. 결승 접근 구슬의 점진 감속 v13 (2026-10-15)

요청: 결승 부분에 도착한 구슬이 더 느려져 마지막 회전봉 앞에서 극적인 역전의 여지가 생기도록 한다.

### 구현과 결정

- 최신 독자 템플릿 3종에 선택 규칙 `finishPace: "dramatic-v1"`을 넣었다. 결승선 12단위 전부터 마지막 5단위까지 smoothstep으로 구슬의 linear damping을 0→6으로 점차 높이며, 마지막 5단위에서는 6을 유지한다. 원본 v13 결승 y=142 기준 감속 시작은 y=130, 최대 감쇠 시작은 y=137이다. 값은 설계 파라미터이며 실제 속도/완주 시간 측정값이 아니다.
- 계산은 순수 core 함수 `finishDamping(y,finishY)`에 두고 `ArcadeFlow.prepareStep`이 매 고정 tick의 Rapier world.step 전에 실제 활성 구슬 body의 setLinearDamping을 설정한다. 감쇠 값이 같으면 setter를 반복 호출하지 않는다. 화면/RAF/게임 전체 시간을 늦추거나 결과 표시를 기다리는 방식이 아니다.
- 감속은 구슬의 실제 위치만으로 정하며 이름·ID·현재 순위·선두 여부·참가자 수를 사용하지 않는다. 먼저 접근한 구슬은 먼저 감속하고, 뒤의 구슬은 같은 위치에 도착하면 같은 감속을 받는다. 역전이 반드시 발생하거나 특정 참가자가 이기도록 결과를 정하는 처리는 없다.
- 중력 9.81·1/60 timestep·구슬 크기/질량·회전봉의 tick 운동·접촉 킥·120tick 정체 해소·기존 최대 속도 18을 유지한다. 구슬을 속도 0으로 고정하지 않고 Rapier가 중력/충돌/감쇠를 함께 적분한다. 회전봉이 튕긴 직후의 속도도 이후 tick에서 감쇠되므로 실제 마지막 접전의 강도와 정체 여부는 플레이 확인이 필요하다.
